# Changelog

All notable changes follow [Keep a Changelog](https://keepachangelog.com) and [Semantic Versioning](https://semver.org).

## [1.20.0]

Adds the **`oscillator`** family (the twenty-first family): the packaged active frequency source — a part that contains a resonator (quartz, MEMS, or silicon) plus an active sustaining/output stage, distinct from the passive `crystal` family already shipped. The **second consecutive zero-new-unit family** (after `optocoupler`) — every quantity maps onto the existing closed enum. Synthesized from a 20-datasheet corpus spanning simple XO/SPXO (SiT8008, ASV, ECS-2033, SG-8018), TCXO (SiT5356, ASTX-H11, TG-5021, NSC5318), VCXO/DCXO (V514, ABV0225, SiT3521, VG-4513), OCXO/MCXO (AOCJY, IQOV-164, OH300, MX-503), and low-jitter differential parts (SiT9365, SiT9501, SG3225, 8N4Q001), across SiTime, Abracon, Epson, ECS, NDK, Connor-Winfield, IQD, Vectron/Microchip, and Renesas/IDT. One dictionary spans every sub-type over a shared core, discriminated by which optional keys are present — the same "presence of keys is the signal" pattern the `led` and `optocoupler` families use. The five examples went through both adversarial re-verification (all SHAs byte-confirmed, every ppb→ppm conversion recomputed) and a completeness critic, which drove a same-release 1.1 dictionary bump.

### Added
- **Zero new units** — the load-bearing result. SSB phase noise (`dBc/Hz`) → `dB` arrayed over the `F_OFFSET` (carrier-offset) axis with the "/Hz" and carrier in `conditionsVerbatim` (the ADC-NSD / laser-RIN / crystal precedent); all jitter (RMS phase jitter integrated over a band, RMS period, cycle-to-cycle, peak-to-peak) → `s` with the rms-vs-peak-to-peak distinction in the measurement `statistic`; Allan deviation σy(τ) → `1` (dimensionless fractional frequency, the crystal `quality_factor` precedent) arrayed over the `TAU` (averaging-time) axis; frequency stability / tolerance / aging / pull range → `ppm` where **a printed ppb is ×1e-3** (the family's #1 normalization) and aging is bounded ppm over a named `AGING_PERIOD` window (per_day / first_year / 5_year / 10_year / 20_year), never ppm/year; frequency-vs-temperature slope → `ppm/degC` (ppb/°C ×1e-3); tuning slope → `ppm/V`; warm-up/steady-state power → `W`; warm-up/start-up time → `s`. No schema change, so no unit fixtures. Deliberate non-adds kept in `conditionsVerbatim`: g-sensitivity / acceleration sensitivity (ppb/g — printed only as typicals or ordering options on premium/defense OCXOs, never a guaranteed min/max row; stored as a `ppm` magnitude with the per-g basis in verbatim, with a documented additive path to a future `ppm/(m/s2)` unit if a precision/aerospace push needs numeric cross-part comparison — the deferred-unit precedent, like lux/W-m² for photodiode); the dynamic frequency-vs-ramp rate (ppb/s); shock/vibration g-levels (a note-only qualification-`TEST` axis, the crystal precedent); and dBm output power (→ `W`, printed form verbatim).
- `oscillator` dictionary ([`dictionary/oscillator-1.0.json`](dictionary/oscillator-1.0.json), **67 parameters, 342 aliases**). Groups: **frequency** (`nominal_frequency`), **stability** (`frequency_stability` over temp, `frequency_tolerance` initial, `frequency_stability_vs_supply`/`_vs_load`, `frequency_temperature_slope`, `frequency_hysteresis`, `aging` over `AGING_PERIOD`, `total_frequency_stability`, `allan_deviation` over `TAU`, `holdover`), **supply** (`supply_voltage`, `supply_current` over `F`, `standby_current`, `disable_current`, `reference_voltage`, `absolute_max_supply_voltage`, `esd_hbm`), **output** (`duty_cycle`, `rise_time`/`fall_time`, single-ended `output_high_voltage`/`output_low_voltage`, `differential_output_swing`, `output_offset_voltage`, `clipped_sine_output_level`, `output_power`, load capacitance/resistance, `output_impedance`, `harmonic_suppression`, `spurious`), **control** (`input_high_voltage`/`input_low_voltage`, `oe_input_impedance`), **timing** (`startup_time`, `enable_time`, `disable_time`, `resume_time`, `time_to_stability`), **jitter** (`rms_phase_jitter` over `INTEG_BW`, `rms_period_jitter`, `cycle_to_cycle_jitter`, `peak_to_peak_jitter`), **phase_noise** (`phase_noise` over `F_OFFSET`), **tuning** (the VCXO block — `absolute_pull_range`, `pull_range`, `pullability`, `tuning_slope`, `control_voltage_range`, `control_voltage_bias`, `control_input_impedance`, `control_input_bandwidth`, `tuning_linearity`), **oven** (the OCXO block — `warm_up_time`, `warm_up_power`, `steady_state_power`, `warm_up_accuracy`, `retrace`, `g_sensitivity`), and **thermal**.
- Five real examples, one per sub-type: `oscillator-sit8008` (MEMS simple XO — supply current over frequency, period + two-band phase jitter, the inclusive total-stability routing), `oscillator-sit5356` (MEMS Super-TCXO — the ppb→ppm exemplar: stability/aging in ppb, phase noise over 8 offsets, Allan deviation over TAU, a 3-row temp slope), `oscillator-cw-v514` (quartz LVDS VCXO — the tuning block, differential swing with peak-to-peak statistic, phase noise over offset), `oscillator-cw-oh300` (Stratum-3E quartz OCXO/VCOCXO — the oven block, Allan deviation over TAU, phase noise per carrier band), and `oscillator-epson-sg3225een` (quartz LV-PECL clock — inclusive frequency tolerance, femtosecond phase jitter arrayed over carrier frequency).
- New condition axes (spec §7.1, all note-only or reusing existing dimension rules — no schema change since `condition.param` is an open string): `F_OFFSET` (SSB phase-noise carrier offset), `TAU` (Allan-deviation averaging time), `INTEG_BW` (jitter integration band), and note-only `SUBTYPE` (spxo/tcxo/vcxo/vctcxo/dcxo/ocxo/vcocxo/mcxo), `TECHNOLOGY` (quartz/mems/silicon), `OUTPUT_TYPE` (cmos/lvcmos/hcmos/lvpecl/lvds/hcsl/clipped_sine/sinewave), `PLL_MODE`, `STABILITY_GRADE`; `AGING_PERIOD` reused. New pin functions (spec §5): `OUT`/`OUT_N` (differential complementary), `VDD`/`VCC`/`GND`, `OE`/`EN`/`ST`, `VC` (control voltage / EFC), `NC`/`NF`, `VREF`.

### Note on verification
- Every example was fetched as a real PDF (SHA-256 recorded), verified against its source page by the builder, then **adversarially re-verified** by independent agents that re-fetched and re-hashed each PDF (all five byte-identical) and **recomputed every ppb→ppm ×1e-3 conversion** — the family's headline risk — across 15+ affected values in the two SiTime documents with zero 1000× errors, plus grade-discipline checks (the SiT5356 built the Stratum-3+ grade only, excluding the Stratum-3 sub-table and its ±4.6 ppm 20-year total; the OH300 tracked its 0–70 °C grade's warm-up power, not a wider-temp column). Phase noise was confirmed stored as `dB` over `F_OFFSET`, Allan deviation as `1` over `TAU`. Builders repeatedly caught and corrected supplied corpus values against the bytes (SiT8008's currents were the 1.8 V-rail column, not 3.3 V; the V514 phase-noise table has 5 offsets, not 6). A same-release dictionary **1.1** folded in the completeness critic's findings, all reusing existing units: two new keys (`soldering_temperature` in `degC` — the peak reflow rating printed on four witnessed parts, the `optocoupler` precedent; `absolute_max_control_voltage` in `V` — the VC/EFC pin stress rating, symmetric with `absolute_max_supply_voltage`) and five vendor-alias enrichments. The critic reconfirmed that g-sensitivity, the ppb/s dynamic rate, input capacitance, tri-state leakage, and PSRR are correctly absent (each appears only as a typical, a test-method row, or a marketing plot — never a guaranteed min/max). The scope boundary holds: clock generators / PLLs / jitter cleaners (frequency synthesis or distribution — the Renesas 8N4Q001 is the documented boundary case, modeled for its guaranteed output specs with its PLL/divider register map out of scope), RTCs, and the passive crystal are separate families. The V514 example's ordered frequency was re-anchored to the datasheet's own 148.5 MHz ordering example for provenance traceability.

## [1.19.0]

Adds the **`optocoupler`** family (the twentieth family): the optoisolator — an LED emitter coupled to a photodetector across a galvanic-isolation barrier in one package. The **first family since the 1.12 passives batch to need zero new units** — every quantity maps onto the existing closed enum. Synthesized from a 20-datasheet corpus spanning phototransistor (4N35, PC817, EL817, TLP785), high-speed logic (6N137, HCPL-2601, VO2611, TLP2361), gate-drive (HCPL-3120, ACNW3190, FOD3120, TLP350, TLP5754), linear (IL300, HCNR201), photodarlington (TLP627M), photo-triac-driver (MOC3021M, MOC3063), and photovoltaic MOSFET-driver (VOM1271) parts, across Vishay, Broadcom (Avago/HP), Toshiba, Sharp, Everlight, Lite-On, and onsemi/Fairchild. One dictionary spans every output architecture over a shared LED-input and isolation-barrier core, discriminated by which output-block keys are present — the same "presence of keys is the signal" pattern the `led` family uses for photometric-vs-radiometric. The five examples went through both adversarial re-verification (all SHAs byte-confirmed, every base-SI conversion recomputed) and a completeness critic, which drove a same-release 1.1 dictionary bump.

### Added
- **Zero new units** — the load-bearing result. Current transfer ratio → `%` (alt `1`); every isolation rating (VISO/VIORM/VIOTM/VIOSM/VPR) → `V` with the printed Vrms/Vpeak distinction carried by the measurement `statistic` (rms/peak), not a unit; CMTI and triac dv/dt → `V/us` (kV/µs × 1e3, but a printed V/µs is stored as-is); data rate → `Hz` (MBd × 1e6, binary NRZ); linear-coupler transfer gain K3 = K2/K1 and the servo/forward gains K1/K2 → `1`; nonlinearity → `%`; gain tempco → `ppm/degC`; VF tempco → `V/degC`; CTI → `V` (a tracking index literally in volts, alt `1`); creepage/clearance/internal-insulation-thickness → `m`. No schema change, so no unit fixtures. Deliberate non-adds kept in `conditionsVerbatim`: partial-discharge charge (`pC` — a test-acceptance criterion, not a device value; VPR in `V` is the value), humidity `%RH`, and `MBd` baud. The `m`-unit note (spec / build guide) is broadened: creepage/clearance/insulation-thickness are legitimate safety-insulation `m` values, while a mechanical package outline remains excluded.
- `optocoupler` dictionary ([`dictionary/optocoupler-1.0.json`](dictionary/optocoupler-1.0.json), **93 parameters, 493 aliases** — the deepest alias set of any family). Groups: **input** (LED forward voltage/current, reverse voltage/current/breakdown, capacitance, VF tempco), **transfer** (the output-type-discriminating headline: `current_transfer_ratio` and `saturated_ctr` for phototransistor/Darlington; `input_threshold_current`/`input_threshold_voltage`/`input_current_off` for logic; `led_trigger_current` for triac; `transfer_gain` K3 / `servo_gain` K1 / `forward_gain` K2 / `transfer_gain_nonlinearity` / `transfer_gain_temp_coefficient` for linear), **output** (phototransistor VCE(sat)/dark-current/breakdowns/base-pin block; logic levels, supply, enable, fanout; gate-drive peak source/sink current, UVLO rising/falling, on-resistance; triac off/on-state voltage, holding current, `static_dv_dt`; photovoltaic open-circuit voltage / short-circuit current), **isolation** (the headline block — withstand/working/transient/surge/partial-discharge voltages, resistance, barrier capacitance, creepage/clearance/insulation-thickness, CTI, and the 60747-5-5 safety-limiting current/power/temperature), **dynamic** (rise/fall/turn-on/turn-off/storage times, propagation delay high/low, pulse-width distortion, delay skew, enable delay, cutoff frequency, data rate, `common_mode_transient_immunity` arrayed over output state, `common_mode_rejection_ratio`), and **thermal**.
- Five real examples, one per output architecture: `optocoupler-4n35` (phototransistor, base pin brought out — CTR array, base-out breakdown block), `optocoupler-6n137` (10-Mbaud open-drain logic — input threshold current, |CMH|/|CML| CMTI arrayed by `OUTPUT_STATE`, open-drain leakage + pull-up), `optocoupler-acnw3190` (reinforced-isolation IGBT gate driver — the full 60747-5-5 safety block, peak source/sink current, UVLO), `optocoupler-il300` (linear — dimensionless transfer gain K3 = K2/K1, gain tempco, CMRR), and `optocoupler-moc3021m` (random-phase photo-triac driver — the curve-only `characterized` static dv/dt, an explicit `limitClass` test).
- New condition axes (spec §7.1, all note-only or reusing existing dimension rules — no schema change since `condition.param` is an open string): `OUTPUT` (output-type discriminator), `OUTPUT_STATE` (high/low, arraying CMTI and supply current), `SWITCH` (zero-cross vs random-phase triac), `CHANNEL` (multi-channel parts), `I_PD`/`V_PD`/`V_DET` (a linear coupler's photodiode current and bias), and `I_TM`/`V_MT` (a triac driver's on-state current and main-terminal voltage). New pin functions (spec §5): `ANODE`/`CATHODE` (LED input, polarity-symmetric on AC-input parts), `COLLECTOR`/`EMITTER`/`BASE` (phototransistor), `VO`/`VE`/`VCC`/`GND`/`VEE` (logic/gate-drive), `MT` (photo-triac main terminals).

### Note on verification
- Every example was fetched as a real PDF (SHA-256 recorded), verified against its source page by the builder, then **adversarially re-verified** by independent agents that re-fetched and re-hashed each PDF (all five byte-identical), recomputed every base-SI conversion, and checked min/typ/max labels against the physical table column. Both CMTI normalization traps were confirmed correct (the 6N137 prints `1000 V/µs` → value 1000, no conversion; the ACNW3190 prints `15 kV/µs` → value 15000, × 1e3) and the MOC3021M curve-only dv/dt was correctly stored as `characterized`, not the fabricated 100 V/µs seen on Motorola-lineage mirrors (one mislabeled "MOC3021M" mirror turned out to be a TI TPS62150 sheet — caught by content inspection). A same-release dictionary **1.1** folded in the completeness critic's findings, all reusing existing units: five new keys (`common_mode_rejection_ratio` in `dB`, `input_threshold_voltage` in `V`, `output_reverse_voltage`, `output_surge_current`, `output_voltage_abs_max` — the last four promoting guaranteed rows the verifiers found had no home), ~8 vendor-alias enrichments, and one alias tightening (dropping the ambiguous bare "common mode rejection" from the V/µs CMTI key so an extractor cannot route a dB CMRR into it). The scope boundary was stress-tested and holds: the VOM1271 (titled "solid-state relay" but with no integrated load switch — it only drives an external MOSFET) is correctly in-family as photovoltaic, while a load-carrying CPC1017N and the LED-less digital isolators and isolation amplifiers are named as separate future families. A cross-part convention was set for the headline isolation withstand: it is stored in the `max` slot with `absolute_max` (the diode VRRM precedent), so the rating is queryable on one bound across parts.

## [1.18.0]

Adds the **`photodiode`** family (the nineteenth family): the semiconductor photodetector — the receiver that completes the optoelectronic set alongside the LED and laser-diode emitters. Synthesized from a 20-datasheet corpus spanning silicon PIN/PN photodiodes (UV/visible/NIR), avalanche photodiodes (APD), silicon photomultipliers (SiPM/MPPC), InGaAs telecom detectors, and position-sensitive (PSD) / quadrant detectors, across Hamamatsu, Thorlabs, ams-OSRAM, Vishay, Excelitas, onsemi/SensL, Laser Components, and First Sensor. It reuses the emitter envelope **inverted** — the emitter measures optical watts out per drive amp, the detector amps of photocurrent out per incident watt. Three additive units; the five examples went through both adversarial re-verification and a completeness critic. Phototransistors, ambient-light-sensor ICs, optocouplers, camera image sensors, and solar cells are intentionally out of scope.

### Added
- **Three additive units.** `A/W` (amperes per watt) — a detector's responsivity/photosensitivity, the photocurrent per incident optical watt and the literal reciprocal of a laser's `W/A` slope efficiency (a printed `mA/mW` is the identical number; using the emitter's `W/A` for a detector inverts the transfer direction, which the negative fixture rejects). `W/sqrtHz` (watts per root-hertz) — the noise equivalent power (NEP), completing the noise-density family alongside the existing `V/sqrtHz`/`A/sqrtHz`. `m2` (square metres) — a detector's photosensitive/active area (`mm²` → `1e-6 m²`), a first-class selection parameter distinct from a wavelength or a diameter in `m`. All additive; every previously valid document stays valid. Positive fixture `valid/photodiode-responsivity-nep-area.json`; negative fixture `dictionary-invalid/responsivity-in-watts-per-amp.json`. Spec §9. Deliberately *not* added: `lx`/`W/m2` (a detector's illumination stimulus stays in `conditionsVerbatim` — they belong to the future phototransistor / ambient-light-sensor families) and the D* "Jones" detectivity (derivable from NEP and area).
- `photodiode` dictionary ([`dictionary/photodiode-1.0.json`](dictionary/photodiode-1.0.json), 52 parameters, 263 aliases). The optical core (`responsivity` in `A/W` arrayed over the incident-wavelength `LAMBDA` axis, `quantum_efficiency`, `peak_wavelength`, `spectral_response_range`, `nep` in `W/sqrtHz`), the electrical block (`dark_current` and `terminal_capacitance` arrayed over reverse voltage, `shunt_resistance`, `reverse_voltage`), the mechanical `photosensitive_area` (`m2`) / `photosensitive_diameter` (`m`), and four sub-type blocks: avalanche (`breakdown_voltage`, `multiplication_gain` arrayed over reverse voltage, `excess_noise_factor`/`excess_noise_k_factor`, `temperature_coefficient_breakdown_voltage`, `noise_current_density`), SiPM (`photon_detection_efficiency`, `dark_count_rate`, `crosstalk`, `afterpulsing`, `number_of_microcells`, `microcell_size`, `fill_factor`, `temperature_coefficient_gain`), and position-sensing (`position_resolution`, `position_detection_error`, `interelectrode_resistance`, `saturation_photocurrent`, `segment_gap_width`, `segment_matching`).
- Five real examples across the sub-types: `photodiode-hamamatsu-s1223` (silicon PIN — the `A/W` responsivity-vs-wavelength array, `W/sqrtHz` NEP, `m2` area), `photodiode-hamamatsu-g12180` (InGaAs telecom — responsivity at 1.3/1.55 µm, `shunt_resistance`, diameter in `m`), `photodiode-excelitas-c30902` (silicon avalanche — at-gain responsivity, `multiplication_gain`, `breakdown_voltage` and its `V/degC` tempco, the excess-noise k-factor), `photodiode-onsemi-microfc60035` (silicon photomultiplier — PDE, dark-count-rate, ~3×10⁶ gain, crosstalk, microcells), and `photodiode-hamamatsu-s5990` (2-D position-sensitive detector — position resolution and detection error in `m`, interelectrode resistance).
- New condition axes (spec §7.1): `LAMBDA` (incident-light wavelength, unit `m` — the axis a detector's responsivity/spectral-response is swept over) and `M` (avalanche multiplication gain, dimensionless — the axis an APD's dark current, bandwidth, and excess-noise factor are swept over). New pin functions (spec §5): a photodiode reuses `ANODE`/`CATHODE`; a SiPM adds a `FAST` timing output; a PSD uses `X1`/`X2`/`Y1`/`Y2`; a quadrant detector uses `SEG_A`…`SEG_D` with a shared `COMMON`.

### Note on verification
- Every example was fetched as a real PDF (SHA-256 recorded), re-checked against its source page, then **adversarially re-verified** (both SHAs confirmed, every base-SI conversion recomputed, min/typ/max labels checked against the physical table column via word x-coordinates) and put through a **completeness critic**. Two real defects in the SiPM example were caught and fixed before shipping: `dark_current` (618 nA) and `dark_count_rate` (1200 kHz) were stored as `min` but are the datasheet's `typ` (the part prints no min column) — and a prior 1000× dark-count-rate normalization error (1.2e9 → the correct 1.2e6 Hz) was caught and corrected in both the value and the dictionary hint. The completeness critic drove eight additive keys — `dark_current_temperature_factor` (the multiplicative TCID row, on 4/5 datasheets, previously lossy in `conditionsVerbatim`), the abs-max `forward_current`/`reverse_current` and `soldering_temperature` ratings, and the SiPM `quench_resistor`/`microcell_recovery_time`/`single_photon_time_resolution` plus the InGaAs-APD `excess_noise_index` (the `F=M^x` alternate to the k-factor) — a deep vendor-alias sweep, and one correctness fix: `nep` was wrongly *required* (many valid Si-PIN/PSD datasheets omit it) and is now optional.

## [1.17.0]

Adds the **`laser_diode`** family (the eighteenth family): the semiconductor laser diode, synthesized from a 20-datasheet corpus spanning Fabry-Perot edge emitters (visible red, IR pump), single-frequency DFB/DBR sources (telecom 1310/1550 nm, atomic-reference 780 nm), VCSELs (850 nm datacom, 940 nm sensing), and high-power multimode single-emitters and fiber-coupled modules, across Thorlabs, Ushio, Eblana, LD-PD, ams-OSRAM, Broadcom, VI Systems, BWT, PAM-XIAMEN, and Nichia. It reuses the LED/diode measurement envelope with a disjoint vocabulary — textbook "one envelope, many families." Two additive units; the five examples went through both adversarial re-verification and a completeness critic. Laser-diode driver ICs, photodiodes, and optical transceivers are intentionally out of scope.

### Added
- **Two additive units.** `W/A` (watts per ampere) — a laser's slope (differential) efficiency `dP/dI`, the slope of its optical-power-versus-drive-current curve (a printed `mW/mA` is the identical number, no scale factor); printed on 3–4 of every 4 corpus parts. `m/A` (metres per ampere) — a single-frequency laser's wavelength current-tuning coefficient `dλ/dI` (`nm/mA` → `m/A` ×1e-9), the fast tuning knob whose VBG-stabilized-vs-free-running contrast (~0.03 vs ~1 nm/A) is a real comparable design figure. All additive; every previously valid document stays valid. Positive fixture `valid/laser-slope-tuning-units.json`; negative fixture `dictionary-invalid/slope-efficiency-in-watts.json` (slope efficiency asserted in `W` is rejected). Spec §9. A laser's linewidth stays a frequency width in `Hz`, its SMSR and RIN stay `dB` (the RIN's per-`Hz` reference kept in `conditionsVerbatim`, the ADC-NSD precedent), and its `M²`/numerical aperture stay `1` — no further units needed.
- `laser_diode` dictionary ([`dictionary/laser_diode-1.0.json`](dictionary/laser_diode-1.0.json), 53 parameters, 376 aliases). The optical block (`threshold_current`, `operating_current`, `optical_output_power` arrayed over drive current with its COD ceiling by `limitClass`, `slope_efficiency` in `W/A`, `power_conversion_efficiency`), the spectral block (`center_wavelength`, `spectral_width`, coherent `linewidth` in `Hz`, `side_mode_suppression_ratio`, `wavelength_temperature_coefficient`, `wavelength_current_coefficient` in `m/A`, `relative_intensity_noise`), the beam block (`beam_divergence_parallel`/`_perpendicular` for edge emitters and symmetric `beam_divergence` for VCSELs, `beam_quality_m2`, `astigmatism`, `numerical_aperture`), an optional `monitor_pd` block (the back-facet monitor photodiode's current/dark-current/capacitance/reverse-voltage — present only when the package includes one), an optional `cooler` block (`tec_current`, `thermistor_resistance` — the pigtailed module's TEC/thermistor, which share the orderable MPN), and the datacom `modulation` block (`modulation_bandwidth`, `data_rate`, `rise`/`fall_time`).
- Five real examples across the sub-types: `laser_diode-thorlabs-l980p010` (980 nm Fabry-Perot — `W/A` slope efficiency, the monitor photodiode, edge-emitter astigmatism and ∥/⊥ divergence), `laser_diode-eblana-ep1550dmb` (1550 nm DFB — kHz `linewidth`, `side_mode_suppression_ratio`, `wavelength_current_coefficient` in `m/A`, and the TEC/thermistor cooler block), `laser_diode-visystems-v25-850` (850 nm 25 Gbit/s datacom VCSEL — `modulation_bandwidth`, `differential_resistance`, RMS spectral width, symmetric divergence), `laser_diode-bwt-k976da3rn` (976 nm 30 W fiber-coupled pump — multi-watt power, amp-scale threshold, fiber core/NA), and `laser_diode-osram-plpt9-450` (450 nm 7 W blue single-emitter — `thermal_resistance_junction_case`, polarization ratio, and the no-monitor-photodiode case).
- New condition axis (spec §7.1): `P_OUT` (rated optical output power, unit `W` — the point a laser's threshold/voltage/wavelength/monitor-current are quoted at). New pin functions (spec §5): `LD_ANODE`/`LD_CATHODE` for the laser junction and `PD_ANODE`/`PD_CATHODE` for the back-facet monitor (so the pinout distinguishes the two junctions sharing the package), with `TEC_P`/`TEC_N` and `THERM` for a temperature-controlled module.

### Note on verification
- Every example was fetched as a real PDF (SHA-256 recorded), re-checked against its source page, then **adversarially re-verified** and put through a **completeness critic**. The critic drove a set of additive keys before shipping — `power_dissipation`, `reverse_current`, `soldering_temperature`, `optical_isolation`, `beam_angle_deviation`, `emission_point_accuracy`, `number_of_emitters`, `aperture_diameter`, `wavelength_tuning_range`, `kink_free_power`, `thermistor_beta`, `fiber_cladding_diameter` — and a batch of vendor-symbol aliases (Greek `θ`/`λ`/`η`/`Δν`, and `Popt`, the primary output-power symbol that was missing). The only real fix that pass produced was narrowing the OSRAM `center_wavelength` to the 7 W grade's 434–450 nm range (one grade per document).

## [1.15.0]

Adds the **`crystal`** family (the sixteenth family): the passive quartz crystal unit / resonator, synthesized from a 20-datasheet corpus spanning 32.768 kHz tuning-fork, MHz AT-cut SMD (fundamental and overtone), automotive / AEC-Q200, and through-hole HC-49 parts across Abracon, Epson, NDK, Kyocera, Citizen, TXC, Pletronics, and QST. Two additive schema changes — two new units — and the four examples went through both adversarial re-verification and a completeness critic. The active clock sources that *contain* a crystal (XO / TCXO / VCXO / OCXO) are intentionally a **separate future family**, not folded in here.

### Added
- **Unit `ppm/degC2`** (ppm per degree-Celsius-squared, ppm·K⁻²): the second-order (parabolic) temperature coefficient a 32.768 kHz tuning-fork crystal publishes about its turnover temperature, where `Δf/f = coefficient × (T − T_turnover)²`. It is the defining thermal spec of that cut (universally ≈ −0.035…−0.04 ppm/°C², printed on 4/4 tuning-fork parts in the corpus) and cannot be represented by the linear `ppm/degC` — the two are not interconvertible. Carried as a first-class value rather than buried in `conditionsVerbatim`. Additive; every previously valid document stays valid. Positive fixture `valid/ppm-degc2-parabolic.json`; negative fixture `dictionary-invalid/parabolic-coefficient-linear-unit.json` (the linear unit is rejected). Spec §9.
- **Unit `1`** (dimensionless, ISO 80000's symbol for a quantity of dimension one): a bare ratio or count that is none of `bits` (a base-2 count), `V/V` (a voltage-gain ratio), or `%`/`ppm` (fractions). It carries a crystal's `quality_factor` (Q) and `capacitance_ratio` (C0/C1), both pure numbers that datasheets print as guaranteed spec rows. Added after the completeness critic found these printed on real parts (Statek publishes Q; the flagship `crystal-abs07` prints Q = 10000/30000) with nowhere to land — dropping a printed, guaranteed value would violate the schema's core invariant. Additive; positive fixture `valid/dimensionless-quality-factor.json`. Spec §9.
- `crystal` dictionary ([`dictionary/crystal-1.0.json`](dictionary/crystal-1.0.json), 20 parameters, 223 aliases). The frequency block (`nominal_frequency`, `frequency_tolerance`, `frequency_stability` — a total ppm excursion over a temperature *range*, never `ppm/degC`), the tuning-fork thermal pair (`parabolic_coefficient` in the new unit + `turnover_temperature`), the RLC equivalent circuit (`equivalent_series_resistance`, `load_capacitance`, `shunt_capacitance`, `motional_capacitance`, `motional_inductance`) plus the dimensionless `quality_factor` and `capacitance_ratio`, `drive_level` (operating vs absolute-max survivable, split by `limitClass`, not by separate keys), `drive_level_dependency`, `insulation_resistance`, `aging` (a bounded ppm figure over a stated window, not a `ppm/year` rate), `environmental_frequency_shift`, and `spurious_response`. `equivalent_series_resistance` is single-valued per orderable grade — a datasheet's ESR-per-frequency-band table is a family ordering artifact across MPNs (and a wider-temperature, higher-ESR row is a *different grade*), so one document emits one ESR value, not the table.
- Four real examples across the sub-shapes: `crystal-abs07` (Abracon 32.768 kHz tuning-fork — the `ppm/degC2` parabolic coefficient, turnover temperature, a dimensionless quality factor, and kΩ-scale ESR), `crystal-cx3225gb` (Kyocera 20 MHz AT-cut — an IEC-π-network ESR condition and an eight-element `environmental_frequency_shift` array over the `TEST` axis), `crystal-citizen-hc49us` (Citizen HC-49/U-S 40 MHz through-hole — 3rd-overtone `MODE` and series-resonant load handling, with `load_capacitance` omitted rather than faked), and `crystal-epson-tsx3225` (Epson TSX-3225 24 MHz — the recommended-vs-absolute-max drive split and aging carried over an `AGING_PERIOD` window).
- New condition axes (spec §7.1): `DL` (drive level, unit `W` — the excitation ESR and tolerance are measured at), and the note-only `MODE` (reused: `fundamental` / `3rd_overtone` / `5th_overtone` / `7th_overtone`, selecting the ESR band), `RESONANCE` (`series` vs `parallel` — a series part omits load capacitance), `AGING_PERIOD` (`first_year` / `10_year`), and `TEST` (`shock` / `vibration` / `thermal_shock` / `reflow` / `moisture` / … — the reliability stress a permanent frequency shift is bounded under, its mechanical setup kept in `conditionsVerbatim` and never in the unit enum). New pin functions (spec §5): the symmetric, interchangeable `XTAL1` / `XTAL2` resonator terminals, with a four-pad package's extra pads as the `GND` / case tie.

### Note on verification
- Every example was fetched as a real PDF (SHA-256 recorded), its values re-checked against the source page, and then **adversarially re-verified** (both SHA-256 hashes and every base-SI conversion, min/typ/max role, `limitClass`, and source page confirmed against the datasheet) plus put through a **completeness critic**. The critic drove the additive `quality_factor` / `capacitance_ratio` keys and the `1` unit (a printed, guaranteed Q had nowhere to land), and deepened the alias sets. The adversarial pass corrected three real example defects before shipping: `crystal-abs07` had folded the datasheet's H/W temperature-option grades' ESR rows (95 kΩ) into a document whose MPN is the −40~+85 °C "blank" grade — a violation of one-grade-per-document, reduced to the single 70 kΩ that grade specifies — and had stored a fabricated midpoint for a shunt capacitance whose typ is printed as a range (0.9–1.2 pF), now carrying only the guaranteed max; `crystal-epson-tsx3225` stored a symmetric ±1 ppm aging as `{max: 1}`, now `{min: −1, max: 1}`.

## [1.10.0]

Adds the **`dc_dc`** family, the fifth family and the first switching-power family, built from a 20-datasheet corpus (TI, Analog Devices, MPS, Richtek, Aerosemi) spanning **four sub-shapes under one envelope**: monolithic converters with integrated FETs (buck/boost/buck-boost), external-FET controllers, integrated-inductor power modules, and isolated primary-side-sensing flyback controllers. ### Added
- `dc_dc` dictionary ([`dictionary/dc_dc-1.0.json`](dictionary/dc_dc-1.0.json), 92 parameters). Core switching/reference/protection keys are common; a part's sub-type selects the optional keys. Notable coverage: integrated-FET on-resistance and current limits; controller gate drive in **both** idioms (peak `gate_driver_source_current`/`sink_current` **and** `gate_driver_pullup_resistance`/`pulldown_resistance`); `current_sense_threshold` and `internal_regulator_*` (VCC voltage/UVLO/dropout/current-limit, `external_bias_switchover_*`); a full monitor/protection set (`power_good_*` including output resistance, `uvlo_*`, `overvoltage_protection_threshold` with a percent-of-reference `altUnit`, `thermal_shutdown_threshold`/`_recovery`, `hiccup_time`, `short_circuit_trip_threshold`, `dropout_voltage`, `zero_cross_threshold`); module-level `efficiency`/ripple/transient/accuracy; and external components (`recommended_inductance`, `transformer_turns_ratio`, `leakage_inductance`).
- **Isolated flyback support.** Primary-side-sensing flyback controllers have no VOUT pin and no feedback divider — output voltage is inferred from the primary flyback pulse via an RFB/RREF resistor ratio times the transformer turns ratio. New keys `tc_current`, `flyback_comparator_trip_current`, `transformer_turns_ratio` (V/V), `leakage_inductance` (H), plus boundary/critical-conduction-mode timers `max_on_time`/`max_off_time`/`max_discontinuous_off_time`, and the `sense_threshold_ratio`/`overcurrent_threshold`/`sense_input_bias_current` current-sense keys.
- Three real examples: `dcdc-lmr33630` (TI monolithic synchronous buck: dual-package on-resistance, precision enable, power-good window in percent, hiccup/thermal protection, recommended L/C in henries and farads), `dcdc-lm5116-controller` (TI wide-Vin external-FET buck controller: emulated peak-current-mode ramp currents, gate-driver source/sink and drop-from-rail output voltages, VCCX external-bias switchover, current-sense thresholds), and `dcdc-lt3748-flyback` (ADI isolated no-opto flyback controller: the RREF bandgap reference, RFB/TC primary-side feedback, VC-controlled current limit, boundary-mode timers, and transformer turns ratio).
- Recommended switching pin functions (spec §5): `SW`/`SW1`/`SW2`, `BOOT`/`BST`/`HB`, `TG`/`BG`/`HO`/`LO`/`GATE`, `COMP`/`ITH`, `VCC`/`VCCX`/`EXTVCC`, `CS`/`CSG`/`SENSE`/`SENSE_P`/`SENSE_N`, `PGND`/`AGND`/`SGND`, and the flyback-specific `TC`/`RREF`/`RFB`. - Positive fixture `valid/henry-inductance.json` exercising the `H` unit for a recommended inductor.

### Note on fidelity
- The three examples were adversarially re-verified against their source PDFs. Two provenance-honesty corrections were made to the buck example before shipping: a thermal-shutdown *hysteresis* that had been synthesized by subtraction was replaced with the datasheet's tabulated *recovery temperature*, and a UVLO threshold read from application prose (rather than a guaranteed table) was tagged `guarantee: "typical"` with a reduced `confidence`. A value must trace to what the datasheet actually prints.

## [1.5.0]

### Added
- Optional per-measurement trust fields (additive; every previously valid document stays valid): `guarantee` (`production_tested` | `by_design` | `by_characterization` | `typical`) records the datasheet's specification basis from the footnotes, independent of `limitClass`; `review` (`unchecked` | `confirmed` | `edited`) records extraction review state, mapping directly to an adopter's per-row review vocabulary; and per-value `confidence` (0–1) complements the document-level `provenance.confidence`. `review`/`confidence` are advisory and are not the `verified` flag (spec §7, §8). The value snapshot tracks `guarantee` (an extracted fact) but not `review`/`confidence` (advisory). Fixtures: `valid/measurement-trust-fields.json`; `invalid/bad-guarantee-value.json`, `invalid/bad-confidence-range.json`.
- `voltage_reference` dictionary: `output_capacitance_range` and `input_capacitance` (stability group), the load/bypass capacitance a reference needs for stability; used in the ADR4525 example (1–100 uF C_OUT). Dictionary now 26 parameters, 154 aliases.
- Unit enum: `ppm`, `ppm/V`, `ppm/A` (additive; every previously valid document stays valid). These complete the fractional-rate family alongside the existing `ppm/degC`, so a value a datasheet prints per volt (line regulation), per amp (load regulation), or as a bare fractional change (long-term drift, thermal hysteresis) is captured as printed and stays auditable against the source page, rather than lossily multiplied by VOUT into `V/V`/`ohm`/`%`. Positive and negative conformance fixtures added (`valid/ppm-units.json`; `invalid/bad-ppm-prefixed-unit.json`, which pins that a prefixed `ppm/mA` is still rejected). Normative note in `spec/v1.0/datasheet-spec.md` §9.
- Third component family, `voltage_reference` ([`dictionary/voltage_reference-1.0.json`](dictionary/voltage_reference-1.0.json), 24 parameters, 144 aliases), unifying series (3-terminal) and shunt (2-terminal) references in one vocabulary: the reference voltage is `output_voltage` for a series part and the reverse breakdown voltage for a shunt part, with shared aliases. Adds a shunt current condition axis `I_R` and the pin functions `CATHODE`/`ANODE`. Line/load regulation and drift/hysteresis use the new `ppm/V`, `ppm/A`, and `ppm` units (see above) so they are captured as printed, with the vendor's original form preserved in `conditionsVerbatim`.
- Three real, verified voltage-reference examples grounded in manufacturer datasheets via datasheets.md: TI LM4040 (10 V shunt), TI REF3025 (2.5 V series), and ADI ADR4525 (2.5 V precision series), spanning three manufacturers and both topologies.
- Regression suite (`scripts/regression.mjs`, `npm run regression`, folded into `npm test` and `npm run build` and CI). Hermetic — reads only committed files, no network, no PDF, no model. Checks (1) dictionary integrity the JSON Schema meta-schema cannot express: no duplicate keys, no alias collisions, every `unit` in the schema's closed enum, every `array` param declaring a `conditionAxis`; and (2) value snapshots of every example under `test/regression/snapshots/`, so a silently changed number, unit, condition, or source page fails the build. Regenerate intentionally with `npm run regression -- --update`.
- `CLAUDE.md` build guide: project thesis and invariant, guiding principles, the externally validated design pillars, the add-a-family golden path, two-axis versioning, the hermetic test model, and the GitHub Actions (OIDC) publish flow.

### Removed
- LDO dictionary `has_active_discharge`, an unusable capability flag surfaced by the new integrity check: a boolean has no base-SI unit and so could never appear in a measurement. The capability is signalled by the presence of `active_discharge_resistance`. Dictionary version 1.2. No valid document could have used the key, so nothing that validated before is affected.
